# Exam 3 — Advanced Patterns and Source Control

**Quick answer:** Record a single video of **5 minutes maximum** demonstrating the tasks below in your own ServiceNow Personal Developer Instance (PDI), narrating as you go. This exam covers **Advanced integration patterns, source control, tooling** and is worth **34 points**.

{% hint style="warning" %}
**Members-only review.** Your video is only graded if you are an active **Exam Navigator** member (or any higher tier) of [TechTalk with Bill](https://www.youtube.com/channel/UCMf7pje1x5iZkkEF-Y3PLSA/join). Include your membership email/handle when you submit.
{% endhint %}

## The scenario

Prove you can design a resilient integration and manage your work with source control the way a real ServiceNow team does.

## What you must demonstrate in your video

Complete and narrate each of the following:

1. Describe one **advanced integration pattern** from Module 6 (for example, MID Server, event-driven, or async pattern) and where it applies.
2. Implement a small version of it in your PDI (or show configuration screens).
3. Add **error handling and logging** so failures are visible.
4. Commit your **update set or scoped app** to source control using the tooling covered in Module 7.
5. Explain one operational safeguard you would add before promoting this integration to production.

{% hint style="info" %}
**Time limit: 5 minutes.** Plan your steps before you hit record. Part of the skill is doing this efficiently — just like a real practitioner under deadline.
{% endhint %}

## Grading rubric (34 points)

Each criterion is scored at one of three levels so you know **exactly what you must prove on screen** to earn the points. Your instructor circles the level reached and returns written feedback.

| Criterion | ✅ Full credit — *proof required* | 🟡 Partial credit | ❌ No credit |
|-----------|-----------------------------------|-------------------|--------------|
| **Pattern selection** | **7 pts** — Advanced pattern described accurately with correct use case. | **3 pts** — Pattern named but use case is weak. | **0 pts** — No pattern discussed. |
| **Implementation** | **7 pts** — Working implementation or clear configuration shown. | **3 pts** — Partial implementation. | **0 pts** — Nothing implemented. |
| **Reliability** | **7 pts** — Error handling and logging visibly built in. | **3 pts** — Basic error handling only. | **0 pts** — None. |
| **Source control** | **7 pts** — Commit shown against source control with the covered tooling. | **3 pts** — Source control setup shown but no commit. | **0 pts** — No source control. |
| **Ops safeguard** | **6 pts** — One concrete production safeguard explained clearly. | **3 pts** — Generic safeguard mentioned. | **0 pts** — None. |
| **Total** | | | **/ 34** |

### Evidence checklist (what the grader looks for)

Your video passes most easily when every item below is visibly true on screen:

- [ ] Advanced pattern described with a real use case.
- [ ] Pattern implemented or clearly configured.
- [ ] Error handling and logging are visible.
- [ ] Update set or scoped app is under source control with a commit shown.
- [ ] Concrete operational safeguard is explained.
