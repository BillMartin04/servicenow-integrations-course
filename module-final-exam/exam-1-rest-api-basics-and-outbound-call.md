# Exam 1: API Fundamentals and an Integration Test

**Quick answer:** Prepare and test your work, then record a narrated demonstration of no more than five minutes. This assessment covers Modules 2, 3, 4, 5 and contributes 33 points to the 100 point course total.

{% hint style="warning" %}
Personal review is for active [Exam Navigator members or higher tiers](https://www.youtube.com/channel/UCMf7pje1x5iZkkEF-Y3PLSA/join). The tasks and rubrics are available to everyone for practice; check the submission guide for intake availability.
{% endhint %}

## The scenario

A fictional supplier needs to exchange data with ServiceNow. Explain the contract and demonstrate the integration pattern practised in Lesson 5.1 using synthetic data and an authorized test endpoint.

## What you must demonstrate in your video

1. Explain REST and SOAP using one concrete difference and relate your chosen contract to the test.
2. Show the endpoint, method, applicable headers and sample input without revealing secrets.
3. Run the demonstrated integration pattern and show the successful request and response.
4. Select one returned value and compare it with the result required by your scenario.
5. Demonstrate a controlled invalid input or unavailable mock response and explain the observed result.

Build before recording. Use only your own lab, synthetic data and authorized endpoints; never show passwords, access tokens or client secrets.

## Grading rubric (33 points)

Select full, partial or no credit for each criterion. Add the awarded points and retain the evidence used to justify the score.

| Criterion | Full credit | Partial credit | No credit |
|---|---|---|---|
| API understanding | 7: Clear explanation linked to the contract. | 3: Protocol named but explanation or application is incomplete. | 0: No relevant evidence. |
| Request configuration | 7: The complete sanitized request configuration is shown. | 3: Some configuration shown, but key elements are missing. | 0: No relevant evidence. |
| Successful test | 7: A successful execution is visible and tied to the request. | 3: A result is shown without a clear connection to the request. | 0: No relevant evidence. |
| Data verification | 6: The returned value is checked against the expected result. | 3: Raw output is shown without checking its meaning. | 0: No relevant evidence. |
| Failure and explanation | 6: The failure and its meaning are both shown. | 3: A failure is described but not demonstrated. | 0: No relevant evidence. |
| Total possible | 33 | | |
